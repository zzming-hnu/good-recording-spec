# Feature Specification: good-recording (macOS 屏幕与音频录制工具)

**Feature Branch**: `001-good-recording`
**Created**: 2026-05-07
**Status**: Draft
**Input**: User description: "我要做一个适配于macos的屏幕录制工具，名字叫做
good-recording，核心功能是屏幕录制，并且要求能够录制环境声与系统声音…
（含窗口/分辨率/格式自由选择、随时中断自动保存、仅录音模式；UI 简洁干净，
交互丝滑，预留后续扩展空间）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一键录屏与一键保存 (Priority: P1) — MVP

普通用户打开 good-recording，主界面只看到一个显著的"开始录制"按钮；
点击后立即开始录制整个屏幕，再次点击同一按钮即停止；停止后录制文件
自动保存到本地默认目录，并在主界面与系统通知中给出"已保存 + 在 Finder
中显示"的轻量提示，全程无任何弹窗或另存为对话框。

**Why this priority**: 这是产品的最小可用形态。即使没有任何高级配置，
"打开 → 录 → 存"这条最短路径就能交付屏幕录制的核心价值，并验证整体
链路（采集 → 编码 → 落盘 → 通知）走通。

**Independent Test**: 全新安装 → 第一次启动并按提示授予屏幕录制权限 →
点击主按钮 → 等待 10 秒 → 再点主按钮 → 在用户的视频默认目录下能找到
一个可在 QuickTime Player 与 Finder 预览中正常播放的视频文件。

**Acceptance Scenarios**:

1. **Given** 已授予屏幕录制权限的全新会话, **When** 用户点击"开始录制",
   **Then** 应用立即以默认配置开始录制全屏，主按钮变为"停止录制"，
   并在菜单栏显示一个带计时器的状态项。
2. **Given** 正在录制中, **When** 用户点击"停止录制"或菜单栏停止入口,
   **Then** 应用立即停止采集，将文件持久化到本地默认目录，并显示一条
   含"在 Finder 中显示"操作的"已保存"提示。
3. **Given** 未授予屏幕录制权限, **When** 用户点击"开始录制",
   **Then** 应用以日常用语解释为什么需要授权，并提供"打开系统设置"
   一键入口，不开始录制也不崩溃。

---

### User Story 2 - 选择录制范围 (Priority: P2)

用户在开始录制前可以选择录制目标：整个屏幕（多显示器时可指定哪一块）、
某个具体应用窗口、或屏幕上的自定义矩形区域。

**Why this priority**: 普通用户最常见的诉求之一是只想录某个 App 窗口或
屏幕的一部分而不是全屏，这是从"能用"走向"好用"的关键一步。

**Independent Test**: 在 US1 完成的基础上，可以单独打开"录制范围"切换
到"窗口"并选中一个 Safari 窗口 → 录制 → 停止 → 输出文件中只包含被选中
的 Safari 窗口内容，背景及其他窗口不出现。

**Acceptance Scenarios**:

1. **Given** 准备录制, **When** 用户从范围切换器中选择"窗口"并点击列表
   中的某个窗口, **Then** 录制开始后输出仅包含该窗口画面，分辨率与该
   窗口实际像素一致，且窗口在屏幕上移动时仍持续被跟随采集。
2. **Given** 准备录制, **When** 用户选择"区域"并在屏幕上拖出一个矩形,
   **Then** 录制开始后输出仅包含该矩形区域，且该矩形被记忆作为下次
   "区域"模式的默认值。
3. **Given** 选择了某个窗口后, **When** 该窗口在录制期间被关闭或最小化,
   **Then** 应用不崩溃，自动停止录制并保存已采集到的部分，同时以系统
   通知告知用户原因。
4. **Given** 系统接入了多台显示器, **When** 用户在"整个屏幕"模式下开始
   录制, **Then** 应用要求用户先选择目标显示器（默认为主显示器），
   不会同时录制所有屏幕。

---

### User Story 3 - 音频源选择 (Priority: P2)

每次录制前，用户可以通过两个独立开关选择是否录入：环境音（系统当前
默认输入设备，例如内建/外接麦克风）、系统声音（macOS 当前正在播放
的音频）；两者可独立开关、可同时开启、也可同时关闭（纯静音录屏）。

**Why this priority**: 用户明确把"录制环境声与系统声音"列为核心功能。
这一项决定了录屏作品的最终可用性（教学视频要解说+演示音、游戏录制
要游戏音+解说），缺失则产品价值大幅下降。

**Independent Test**: 在 US1 基础上单独打开音频面板 → 勾选"系统声音"
并取消"环境音" → 在浏览器播放一段视频 → 录制 5 秒 → 停止 → 输出文件
中包含该视频的声音但听不到环境噪声。

**Acceptance Scenarios**:

1. **Given** 准备录制, **When** 用户同时启用环境音与系统声音, **Then**
   输出文件音轨混合两路声音，且无明显失真、回声或时序错位。
2. **Given** 准备录制并启用环境音, **When** 系统未授予麦克风权限,
   **Then** 应用以日常用语提示原因并提供"打开系统设置"入口，不开始录制。
3. **Given** 录制中, **When** 用户拔出当前默认音频输入设备, **Then**
   应用不崩溃并以可见提示告知音频源已变更，视频部分继续录制不中断。
4. **Given** 任意音频开关均未启用, **When** 用户开始录屏, **Then**
   录制照常进行，输出文件包含合法的静音音轨（即文件可被任何播放器
   作为有声视频处理）。

### User Story 4 - 录制质量与格式设置 (Priority: P3)

用户可以在设置中调整录制分辨率（720p / 1080p / 1440p / 原生）与输出
容器格式（默认 mp4，可在受支持范围内切换其他容器，如 mov），且设置
在重启后保留。

**Why this priority**: 提升专业度但不阻塞核心录制流程。普通用户用默认
配置就能用；进阶用户在需要平衡画质与文件大小、或需要兼容特定剪辑/
分享软件时使用。

**Independent Test**: 进入设置 → 把分辨率改为 720p、格式改为 mov →
录制 5 秒 → 输出文件实际短边为 720 像素且容器为 .mov；重启应用后
设置仍保持 720p / mov。

**Acceptance Scenarios**:

1. **Given** 默认设置, **When** 用户将分辨率从"原生"改为"720p", **Then**
   后续所有录制的输出文件短边为 720 像素且画面长宽比保持源画面比例。
2. **Given** 选择某种格式, **When** 该格式在当前 macOS 版本下不可用,
   **Then** 应用以日常用语告知并自动回退到默认格式，不让用户陷入失败
   弹窗或空白文件。
3. **Given** 修改了任意设置, **When** 退出并重启应用, **Then** 设置
   保持上次值。
4. **Given** 用户改动过多项设置, **When** 用户点击"恢复默认", **Then**
   所有设置一键回到出厂默认值，并在恢复前给出二次确认。

---

### User Story 5 - 仅音频录制 (Priority: P3)

用户可以切换到"仅录音"模式，只录制声音而不录制屏幕；声音源选项
（环境音 / 系统音 / 两者）与录屏模式一致。

**Why this priority**: 是录屏功能的合理延伸（同一套权限和音频管线），
适合录会议纪要、播客片段、想法备忘等场景；但不是 v1 必备。

**Independent Test**: 切换到"仅录音" → 选择"环境音" → 录 5 秒 → 输出
一个独立可播放的音频文件（不含视频轨）且大小显著小于同时长视频文件。

**Acceptance Scenarios**:

1. **Given** 切换到仅录音模式, **When** 用户开始录制, **Then** 应用不再
   请求屏幕录制权限，仅请求与已选音源对应的权限。
2. **Given** 仅录音模式, **When** 录制完成, **Then** 输出为标准音频
   文件，可在 QuickTime Player / Music App 中正常播放。
3. **Given** 仅录音模式但未选择任何音源, **When** 用户尝试开始录制,
   **Then** 应用阻止开始并清晰提示"请至少选择一个音源"。

### Edge Cases

- 录制过程中磁盘剩余空间低于 500 MB：应用 MUST 主动停止录制、将已采集
  部分以可播放状态保存、并以系统通知清晰告知原因（"磁盘空间不足，
  录制已自动停止"）。
- 应用被强制退出 / 系统断电 / 系统被强制重启：v1 范围内 MUST 保证用户
  主动停止过的录制文件可播放；非正常终止的录制文件可不保证可播放，
  但 MUST 不在用户视野内留下半成品垃圾文件（或在下次启动时主动询问
  如何处理）。
- 用户在权限授予前点击录制：MUST 引导授权而不是失败崩溃。
- 多显示器场景下"整个屏幕"模式：MUST 让用户选择具体的显示器；
  不主动同时录制所有屏幕。
- 录制期间显示器配置变化（外接显示器拔出、HiDPI 切换）：MUST 不崩溃；
  视频流尽量保持，允许在文件中产生分辨率切换。
- 录制超长时长（例如 > 4 小时）：MUST 不崩溃；如果当前格式不支持
  单文件超大尺寸，MUST 自动分段或在停止时合并，让用户能完整观看。
- 录制开始的瞬间用户切换音频输出/输入设备：MUST 不崩溃；后续录制
  以新设备的音流为准。
- 仅录音模式下系统当前无任何声音输出：MUST 不报错，输出文件为合法
  的（可能为静音的）音频。
- 用户连续高频点击"开始/停止"按钮：MUST 不产生竞态错误、不出现重复
  文件或残留临时文件。

## Requirements *(mandatory)*

### Functional Requirements

#### 录制核心

- **FR-001**: 系统 MUST 提供单一显著的"开始/停止"主按钮，使录制开始与
  停止均可一键完成。
- **FR-002**: 系统 MUST 在用户停止录制后将文件自动持久化到本地默认目录，
  无需用户在另存为对话框做任何操作即可获得最终文件。
- **FR-003**: 系统 MUST 允许用户随时停止录制；从用户点击停止到文件可在
  Finder 中找到的延迟 MUST ≤ 3 秒（针对 ≤ 10 分钟的录制）。
- **FR-004**: 录制中状态 MUST 在 macOS 菜单栏 (status bar) 持续可见，
  包含计时器与"停止"操作，使用户在主窗口被遮挡时仍可一键停止。

#### 录制范围

- **FR-005**: 用户 MUST 能在开始录制前选择录制目标，候选项至少包含：
  整个屏幕、单个应用窗口、用户自定义矩形区域。
- **FR-006**: 当存在多个显示器时，系统 MUST 在"整个屏幕"模式下要求用户
  显式选择目标显示器（默认主显示器），不同时录制全部屏幕。
- **FR-007**: 选择"窗口"模式时，系统 MUST 实时列出当前可见窗口，每项
  附应用图标与窗口标题，并支持搜索/过滤以应对窗口数量很多的场景。
- **FR-008**: 选择"区域"模式时，用户 MUST 能在屏幕上拖动出一个矩形区域；
  最近一次的矩形 MUST 被记忆作为该模式下次默认值。

#### 音频

- **FR-009**: 用户 MUST 能在开始录制前独立设置两个音频源开关：环境音
  （系统默认输入设备）与系统声音；两者 MUST 可独立开关、可同时开启、
  也可同时关闭。
- **FR-010**: 当用户启用了环境音或系统声音但相应权限缺失时，系统 MUST
  在不开始录制的前提下，以日常用语指引用户授权，并提供跳转到 macOS
  系统设置对应面板的一键入口。
- **FR-011**: 当同时录入环境音与系统声音时，系统 MUST 将两路音频混合
  到单一输出文件的音轨中，混合后无明显回声、爆音或时序错位。
- **FR-012**: 当任一音频源在录制中变得不可用（设备拔出、被其他 App
  独占等）时，系统 MUST 不崩溃，应继续录制其余有效音源/视频，并以
  可见提示告知用户。

#### 质量与格式

- **FR-013**: 用户 MUST 能在设置中选择录制分辨率，至少包含 720p、
  1080p、1440p、原生（按目标显示/窗口实际分辨率）四档预设。
- **FR-014**: 用户 MUST 能选择输出文件容器格式，默认 mp4；至少额外
  支持 1 种容器格式（如 mov）作为可选项。
- **FR-015**: 系统 MUST 在用户重启应用后保留分辨率、格式、音频源选择、
  录制范围偏好等所有用户设置。
- **FR-016**: 系统 MUST 提供"恢复默认设置"操作，且在执行前进行二次
  确认。

#### 仅音频模式

- **FR-017**: 系统 MUST 提供"仅录音"模式开关，在该模式下不采集屏幕画面；
  音频源选择与录屏模式一致。
- **FR-018**: 仅音频模式下若用户未勾选任何音源，系统 MUST 阻止开始录制
  并清晰提示原因。
- **FR-019**: 仅音频模式的输出文件 MUST 是可被 macOS 自带播放器
  （QuickTime Player、Music）直接播放的标准音频文件。

#### 文件管理与发现

- **FR-020**: 录制完成后，系统 MUST 在通知与主界面中提供"在 Finder 中
  显示"操作，使用户可立刻定位到刚保存的文件。
- **FR-021**: 默认保存目录 MUST 是 macOS 用户目录下与产品同名的子目录
  （视频默认 `~/Movies/Good Recording/`；音频可放在同目录或
  `~/Music/Good Recording/`，由实现选择，但 MUST 在首次创建后保持一致）；
  用户 MUST 能在设置中自定义此目录。
- **FR-022**: 文件命名 MUST 包含可读的日期时间戳（如 `Recording 2026-05-07
  20.12.33.mp4`），保证 Finder 默认按名称排序即等价于按时间排序。

#### 状态可见性与异常停止

- **FR-023**: 任何因系统/资源原因（磁盘空间不足、权限被回收、目标窗口
  消失等）导致的非用户主动停止 MUST 立即触发自动保存逻辑，并以系统
  通知告知用户原因。
- **FR-024**: 应用 MUST 在用户连续高频操作"开始/停止"按钮时（例如 1 秒
  内多次点击）保持稳定，不产生竞态错误、重复文件或残留临时文件。

#### 隐私与本地优先（与宪法原则 I 对齐）

- **FR-025**: 录制文件、用户设置、本地日志 MUST 全部存储在用户本地设备；
  未经用户在 UI 中显式同意，应用 MUST 不向任何远端服务发送录制内容、
  文件名、使用统计或崩溃报告。
- **FR-026**: 系统 MUST 在"关于"或"帮助"窗口中提供清晰的隐私声明，向
  普通用户说明"什么数据存在哪里、什么时候会发出去（默认：从不）"。

### Key Entities *(本特性涉及的核心数据)*

- **Recording (录制项)**: 一次完整的录制活动产物。属性：标识符、
  开始/结束时间、时长、文件路径、容器格式、最终分辨率、音频轨道组合
  （环境音 / 系统音 / 两者 / 无）、录制范围（全屏-显示器ID / 窗口-应用
  与窗口标题快照 / 区域-矩形坐标）、文件大小、是否被异常终止。
- **RecordingPreset (录制预设)**: 一组可复用的录制配置（分辨率 + 格式
  + 音频源 + 范围模板）。v1 至少包含一个隐式的"上次使用"预设；显式
  多预设管理为后续扩展点。
- **Settings (设置)**: 全局偏好。属性：默认保存目录、默认分辨率、默认
  格式、默认音频源组合、默认录制范围、是否在菜单栏显示计时器、文件
  命名模板。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全新用户从首次启动应用到完成第一次成功录制（含一次权限
  授予流程）MUST 能在 90 秒内完成。
- **SC-002**: 在已授权的常规会话中，用户从打开应用到点击"开始录制"
  的操作步数 MUST ≤ 3 步。
- **SC-003**: 用户停止录制后，能在 Finder 中看到可正常播放文件的等待
  时间 MUST ≤ 3 秒（针对 ≤ 10 分钟的录制）。
- **SC-004**: 一次 30 分钟、1080p、双音轨的录制结束后，文件 MUST 100%
  可被 macOS 自带 QuickTime Player 完整播放，无音轨丢失、无画面损坏。
- **SC-005**: 在内部用户（非工程师）未经引导的情况下，主路径"我想录
  这个窗口的视频，带麦克风"MUST 有 ≥ 80% 的人在 60 秒内自行完成。
- **SC-006**: 默认配置下首次录制完成后，外部网络观察到的来自
  good-recording 的请求数 MUST = 0。
- **SC-007**: 任何一次"用户主动停止"流程结束后，输出文件可播放率
  MUST = 100%（以试点期至少 100 次真实录制为样本）。
- **SC-008**: 应用从冷启动到主界面可交互的时间在 Apple Silicon 上
  MUST ≤ 2 秒（与宪法 macOS 性能基线一致）。
- **SC-009**: 应用在录制 1080p + 双音轨场景下的常驻内存空闲时
  MUST ≤ 200 MB；录制中峰值 SHOULD ≤ 500 MB。
- **SC-010**: 主交互（按下"开始"到 UI 反馈"录制中"）延迟 MUST ≤
  100 ms p95。

## Assumptions

- **目标用户**：普通 macOS 用户（非专业视频工作者），愿意为简洁体验
  放弃部分高级特性。
- **最低支持系统**：默认假设 macOS 13+（Ventura 及更新），以便使用系统
  原生的屏幕与系统音采集能力，无需要求用户安装第三方音频驱动；
  最终版本将在 plan.md 中敲定（与宪法 IV 中的 TODO(MIN_MACOS_VERSION)
  对齐）。
- **"环境音"语义**：指 macOS 当前选定的默认音频输入设备（System
  Settings → Sound → Input 里的当前设备）；多设备同时混合录入与
  设备级 picker 不在 v1 范围内。
- **"系统声音"语义**：指 macOS 当前播放给默认输出设备的全部音频，
  不区分 App 来源；按 App 选择性录制系统音不在 v1 范围内。
- **默认输出格式**：v1 默认 `mp4`；仅录音模式默认 `m4a`。两者均确保
  在 macOS 自带播放器中开箱即用。
- **录制历史视图**：v1 不内置专门的录制历史/相册视图，仅在每次录制
  完成时提供"在 Finder 中显示"。专门的历史视图列入后续迭代候选。
- **崩溃恢复**：v1 不承诺非正常终止（崩溃 / 断电 / kill -9）下的录制
  文件可播放；用户主动停止严格保证可播放。深度崩溃恢复列入后续迭代。
- **暂停 / 恢复**：v1 不支持录制中暂停再继续，只支持开始与停止。
  暂停功能列入后续迭代候选。
- **摄像头 / 画中画 / 鼠标光标特效 / 键盘按键可视化**：均不在 v1 范围内，
  作为后续迭代候选。
- **多语言**：v1 主交互语言为简体中文与英文，跟随系统语言自动切换。
- **应用分发与签名**：通过 macOS 标准方式分发（DMG/PKG，Developer ID
  签名 + 公证），与宪法 IV 的平台一致性要求一致。
- **存储位置**：与宪法 IV 平台约束保持一致（沙箱容器 /
  Application Support / 用户显式选择目录）。
- **可扩展性**：用户提到"预留后续继续更新需求的一些条件"——具体的
  模块化与扩展点设计交由 plan.md 处理；spec 层面通过明确划定 v1 边界
  + 列出"后续迭代候选"清单（见上述 Assumptions）来兜住可扩展性意图。
